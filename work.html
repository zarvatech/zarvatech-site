AI · RAG · On-premise New

A private AI assistant that runs with no GPU and no internet

We gave a government agriculture portal an AI assistant that answers farmers' questions from official scheme documents. It runs entirely on the portal's own locked-down server.

Farmers needed clear answers about government schemes: who qualifies, what share they pay, which documents to submit. Those answers were buried in long PDFs full of tables and abbreviations. The usual AI toolkit wasn't an option, because the server had no GPU, no Python, no Docker and no internet access after setup.

We built the whole assistant in Node.js. A compact open-source language model runs locally on the CPU. Search combines meaning-based matching with exact keyword matching, so scheme acronyms aren't missed. A reranking step then picks the most relevant passages, and strict prompting keeps the model answering only from the documents. All of it fits inside the existing app, starts automatically on reboot, and uses a fraction of the server's memory.

Node.js · llama.cpp · Qwen2.5-3B · Qdrant · BGE embeddings & reranker · MiniSearch (BM25) · Angular

Cloud · AWS · Linux Networking New

30 users, one server, 30 separate network identities

We made a single AWS server send each user's traffic from that user's own pre-registered IP address. That replaced what would otherwise have been a fleet of 30 servers.

The platform connected to an external service that checks the source IP of every request against an address registered for each client. A mismatch means rejection. Giving every user their own server would have multiplied cost and maintenance. The obvious shortcut of binding each request to an IP in code looks right but silently fails on a server with several network interfaces.

We set up one instance with multiple network interfaces and a mix of IPv4 and IPv6 addresses to keep costs down. Each address got its own routing rules, so its traffic leaves through the right interface. We then tracked down three failures that only appear in production: silently rejected routes, a periodic network announcement that scrambled IPv6 traffic every half hour, and an overnight system update that dropped addresses. Finally we added a self-healing check that restores the setup within minutes if anything drifts, plus a test that proves every user's traffic leaves from the right address.

AWS EC2 · ENIs · IPv4/IPv6 · Linux policy routing · netplan · systemd · Node.js
